# First-use repurposing setup

This is an assistant-led conversation, not a background service or new CLI
command. Use it when kopi-video-repurpose lacks confirmed settings for the
requested output. Save personal settings under ignored preferences/repurpose/
and assets under that folder's assets/ directory. Do not put real answers or
assets in tracked examples, skills or docs. No account or connector is required
to answer setup questions.

## Before asking

Read applicable preferences/rules.md, the explicitly selected private profile
and the current brief. Reuse confirmed choices; do not reset existing users.
Load only the requested output's styling. If multiple brands/profiles are present
and the intended one is unclear, ask which to use rather than selecting the first.
Never infer a client, handle or show merely from a familiar host or channel.

Use one local settings file per user-selected brand/project under
preferences/repurpose/<slug>.md. Record shared identity separately from sections
named Shorts, Carousel and Poster. Each section records confirmed choices, asset
paths, references, and deferred decisions. A missing file is not evidence that
an already selected private profile is absent. A shared value applies to an output
only if explicitly marked shared; output-specific overrides stay separate.

## The conversation

Start with the requested output. Ask only the missing essentials in small groups,
using plain language and allowing no branding, use source branding, or decide
later. Do not require setup of all three outputs before doing one.

1. Identity: ask whether to add a handle/name and its exact spelling, whether a
   logo is wanted and whether the user has the actual asset, and preferred placement.
   No handle/logo is a valid answer. Do not invent marks or fetch brand assets
   based on a guessed identity. Record missing assets honestly.
2. Appearance: ask for a reference or offer the generic options in
   REPURPOSE-STYLES.md for the requested output. Discuss colour theme, type and
   caption/text treatment as needed. No brand palette is selected by default;
   a neutral high-contrast treatment may be proposed with the user's agreement.
3. Format: confirm aspect ratio/dimensions, branding placement and output-specific
   preferences. For Shorts also discuss framing, captions, music/sound and pacing;
   for static work discuss panel arrangement, text density and photo use. Read
   existing preferences first so the user need not repeat decisions.
4. Confirm: show a short summary and save confirmed choices locally. Mark undecided
   items as deferred. A user can explicitly accept provisional defaults and start.
   If a meaningful choice still blocks design, keep that choice pending while
   doing independent source analysis. Do not silently mark guesses as approved.

Optional visual comparison uses supplied footage/assets and local tools. The
style descriptions are not pre-rendered or guaranteed pixel-exact templates.
Do not generate paid assets, download a private library, or publish something
merely to illustrate setup. Verify one representative layout before batching.

## Reuse and changes

At later invocations, load the matching settings and ask only about unresolved
choices relevant to the requested output. Do not repeat first-use setup because
a new chat started. A current brief overrides saved defaults; save a temporary
change as a new default only when the user asks. Keep other outputs and brands
unchanged. Preserve the source profile and original assets. These settings
are assistant-readable local files, not new profile install/show modes.

Keep static delivery editable-only with PNG export unless separate images are
requested. Local setup does not enable publishing, uploads, cloud execution,
credential use or paid services.
